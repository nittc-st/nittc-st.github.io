プロコン講習「WEBアプリケーション」の説明資料・Reactの文法・演習指示を1つにまとめた記事です。

この記事の学習目標は次のとおりです。

- WEBアプリケーションの仕組みについて説明できる。
- MVCモデルのWEBアプリケーションを開発できる。
- React及びJSXについて、基本的な文法を習得し、簡単なコンポーネントを実装できる。

ここでは、クライアントサーバシステムを前提として説明する。

## サーバアプリケーション

ユーザのリクエストをサーバが受け取り、サーバがそれを処理して動的にコンテンツを生成するようなソフトウェアをサーバアプリケーションと呼ぶ。

例えば、ユーザからファイル名を取得し、特定のファイルを取得するようなアプリケーション（ファイルサーバ）などがこれに当たる。

もちろん、単なるHTMLを返却するサーバも、URLを解釈してルーティングするアプリケーションである。
（多くは、ApacheやNginxなどといったリバースプロキシと呼ばれるソフトウェアを用いている。）

### WEBアプリケーション

多くの場合、サーバアプリケーションを操作するためのクライアントアプリケーションを用意する。
これを、WEBで用意したものをWEBアプリケーションと呼ぶ。

ここで、WEBアプリケーションを構成する要素のうち、
サーバ上で動作する部分をbackend、ブラウザ上で動作する部分をfrontendと呼ぶ。

### レンダリング

WEBアプリケーションでは、主に二つのレンダリング形式が存在する。
どちらもメリットは存在するが、最近はCSRのほうが多い傾向にある。

#### サーバサイドレンダリング（SSR）

サーバ側でHTMLを生成し、完全なHTMLをクライアントに送信して読み込ませる方法である。

この方法では

- サーバの処理は重くなる
- クライアントの処理は軽くなる
- 1度の通信量は多くなり、ページの読み込みは遅くなる
- 通信回数は少なくなる

#### クライアントサイドレンダリング（CSR）

サーバ側ではデータの処理だけを行い、クライアントがそのデータを取得してHTMLを組み立てる方法である。

この方法では

- サーバの処理は軽くなる
- クライアントの処理は重くなる
- 1度の通信量は少なく、ページの読み込みは速くなる
- 通信回数は多くなる

### CRUD

多くのアプリケーションにおいて、データの操作に必要な機能

- Create（作成）
- Read（読取）
- Update（更新）
- Delete（削除）

これらの頭文字を取り、`CRUD`と呼ぶ。

## MVCモデル

Model-View-Controllerモデルは、WEBアプリケーション（に限らず）の基本的なソフトウェア設計パターンである。

MVCモデルでは、3つの部分が存在する。

1. モデル：データベースを直接操作する
2. ビュー：表示（UI）を定義する
3. コントローラ：モデルを操作し、ビューを更新する

### モデル

モデルは、データベースに対してSQLを投げ、データベースを直接操作する役割を持つ。
例えば、ユーザ一覧を表すデータベースがあれば、モデルは`Users`クラスのようになる。

ある特定のユーザを取得するときは、`Users.get(user)`のようになる。

### ビュー

ビューは、実際にユーザに見える部分を定義する部分である。
他のモジュールで処理した内容を埋め込み、UIを生成する。

### コントローラ

コントローラはユーザからのリクエストに応じて、モデルを操作し、得た値を必要に応じて処理した後、
ビューに埋め込み、ビューをユーザに返却する。

なお、ここでユーザからのルーティングを定義するルータは、コントローラと独立して定義することがある。
（演習のサンプルでも独立して定義している。）

## WEB API

APIとは、他のプログラムがある特定の機能を利用できるようにするためのインタフェースである。

例えば、OSから現在時刻を取得したい場合、`getUnixTime()`関数を実行する。

このAPIの中でも、HTTP通信を使って提供されるAPIを、WEB APIという。

### RESTful API

RESTful APIは、REST原則（Representational State Transfer）に従って設計されたAPIのことであり、
WEB APIにおいて重要な設計方針である。

以下に、RESTful APIの特徴を示す。

**リソース指向**

データや機能をリソースとして扱い、URLで識別を行う。
例えば、ある特定のユーザを得る場合、`/users/1`にGETを送信する。

**HTTPメソッドの役割**

それぞれのメソッドには役割があり、CRUDに対応する。

| メソッド | 役割 | CRUD |
| --- | --- | --- |
| GET | リソースの取得 | R |
| POST | リソースの作成 | C |
| PUT / PATCH | リソースの更新 | U |
| DELETE | リソースの削除 | D |

GETメソッドは、取得のみを行うため、連続で何度実行しても結果が同じになる冪等性をもつ。

**表現形式**

HTMLで直接提供するのではなく、JSON等の形式でやりとりを行う。

### fetch API

fetch APIは、JavaScriptでHTTPリクエストを行うためのインタフェースである。
fetchは関数で提供され、以下のような文法をもつ。（`Promise<Response>`型の値を返却する。）

```js
fetch(/* URL */, {
    method: /* 'GET' | 'POST' | ... */,
    headers: {
        /* ヘッダのエントリ: ヘッダの値 */
    },
    body: /* 文字列化したJSON */
})
    .then(/* 成功時に実行する関数 */)
    .catch(/* 失敗時に実行する関数 */)
```

成功時、fetchはResponse型の値を返す。
Response型は、`ok`や`status`などのフィールド、`text`や`json`などのメソッドをもつ。

## Promise型

Promise型は、JavaScriptで非同期処理を提供するための型である。
Promiseは、以下のような3つのメソッドをもち、引数には関数を指定する。

- `then`：Promiseが成功した時の処理
- `catch`：Promiseが失敗した時の処理
- `finally`：成功失敗のどちらでも最後に実行される処理

### 非同期関数

JavaScriptでは、非同期関数を定義することができる。
非同期関数は、Promiseを扱いやすくするための仕組みである。

非同期関数は、関数定義の前に`async`キーワードを付加することで定義できる。
非同期関数は、返り値を常にPromiseにラップして返却する。

```js
async function 関数名() {
    // 処理
}
```

アロー関数の場合は、次のように書く。

```js
const 関数名 = async () => {
    // 処理
}
```

非同期関数の中では、`await`キーワードを使うことができる。
これは、Promiseが解決するまで待機することを意味する。

ここでは、fetchの例を示す。

```js
async function 関数名() {
    const response = await fetch('http://localhost:8000');
    if (!response.ok) {
        console.log('値の取得に失敗しました');
    }
    return await response.json();
}
```

`await`キーワードはPromise型の値に対して、それが解決されるまで待機する動作を行う。
このときの評価値は、Promiseにラップされていない型をもつ。

つまり、`Promise<Response>`型の値に対して`await`を適用すると、評価された値は`Response`型となる。

## Reactの文法

ReactはWEBサイトのUIの作成に特化したライブラリであり、動的なViewを実装するための機構に特化する。
ReactはJSXというテンプレートファイルを用いて部品（コンポーネント）を実装し、
それをHTMLタグのように呼び出して、UIを組み立てていくことができる。

Reactには、以下のような特徴がある。

### 宣言的なView

Reactでは、宣言的にViewを実装できる。
例えば、挨拶機能を作りたければ、

```jsx
function Greeting({ name }) {
    return <h1>こんにちは、{name}</h1>
}
```

のように記述する。
このように、JSXではJSとHTMLを混合したような文法を用いる。

Reactでは、タグ内で`{}`を使うと、いつでもJSに戻ることができる。
上の例だと、h1タグ内にいても、`{name}`とするとここだけJSとして評価される。

### コンポーネントベース

Reactでは、複数の小さなコンポーネントを組み合わせて画面を構築する。
コンポーネントは画面に含まれる構成要素や部品を定義したものである。

コンポーネントは、HTMLタグのように呼び出すことができる。

```jsx
function App() {
    const [isVisible, setVisible] = useState(false);
    return (
        <div>
            <button onClick={() => setVisible(!isVisible)}>
                { isVisible ? '非表示にする' : '表示する' }
            </button>
            { isVisible && <Greeting name='世界' /> }
        </div>
    )
}
```

### マウントとアンマウント

コンポーネントが画面に表示されるときをマウント、
コンポーネントが画面から削除されるときをアンマウントという。

### useState

Reactで状態を扱うときは、`useState`関数を用いる。

```jsx
const [/* getter */, /* setter */] = useState(/* 初期値 */);
```

getterは、値を取得するときに用いる変数（書き込み不可）である。
setterは、値を設定するときに用いる関数である。

例えば、以下のように用いる。（TypeScriptで型を指定した例）

```tsx
const [error, setError] = useState<Error | null>(null);
// ...
setError(new Error('値の取得に失敗しました'));
```

### useEffect

Reactで副作用を扱うときは、`useEffect`関数を用いる。

```jsx
useEffect(/* 実行する関数 */, /* 依存配列 */);
```

実行する関数は、アンマウント時に実行される関数を返却する。

1. 依存配列が空のとき、マウント時のみ実行される。

```jsx
useEffect(() => {
    console.log('マウントされました');

    return () => {
        console.log('アンマウントされました');
    }
}, [])
```

2. 依存配列に変数を含めるとき、その変数の値が変化したときに実行される。

```jsx
useEffect(() => {
    console.log('秒数が変化しました');
}, [seconds])
```

3. 第二引数を省略すると、レンダリング時に実行される。

```jsx
useEffect(() => {
    console.log('レンダリングされました');
})
```

## 演習

演習では、`1.MVC`〜`4.React`のサンプルプロジェクトを用いる。

### 演習1 MVC

`1.MVC`は、MVCモデルでSSRのWEBアプリケーションを作成した例である。

MVCの各モジュールが、
それぞれ、models、views、controllersディレクトリに格納されている。
そのうち、コントローラは`app.js`で呼び出される。
`app.js`では他にも、サーバの初期化、ルータの生成を行っている。

ただし、ルータはroutesに、生成関数を定義している。

これらが相互にどう作用するのかをよく観察し、
役割を考察せよ。

### 演習2 CSR

`2.CSR`は、HTMLファイルを静的に配置し、
`fetch API`を用いてクライアントからサーバのAPIにアクセスしViewを生成する例である。

ただし、increment、decrementの処理は、サーバにPOSTリクエストし更新している。

演習1との違いを、`public/index.html`の記述をもとに考察せよ。

### 演習3 AJAX

`3.AJAX`は、`2.CSR`に加え、
increment、decrementの処理も`fetch API`を用いている。

つまり、ページを再読み込みするなどしない限り、
ページの読み込みとは独立して値の更新・読み込みが行われる。

これを、非同期読み込み、や`AJAX`という。
（Asynchronous JavaScript And XMLの略であるが、現在は主にJSONでやり取りが行われる。）

この演習について、以下の観点で考察せよ。

- このプロジェクトでModel、View、Controllerがそれぞれどんな役割をもっているか
- WEBブラウザのネットワークトラフィック（実際にどういう通信が行われているか）の記録、スクリーンショット
- データベースの値変化の説明
- クライアントが行う処理とサーバーが行う処理の境界線およびその処理の説明
- Model、View、Controller間のやりとりの図、何がどうしてどうなるかの説明

### 演習4 React

`4.React`は、`3.AJAX`をReactで再実装したものである。
通常のJavaScriptの構文との違いについて、よく確認せよ。

### 演習5 任意のWEBアプリケーションの実装

任意のWEBアプリケーションを実装せよ。

ただし、以下の要件を満たすこと。

- View（フロントエンド）の実装にはReactを用いること
- Model、Controllerの実装はViewとは別に実装すること（バックエンド）
- バックエンドの環境は指定しないが、express.jsを推奨する
- フロントエンドからバックエンドに非同期通信するときは、`fetch API`を用いること
- HTTP通信の標準的なメソッドを用いて、JSON形式でやりとりを行うこと

HTTP通信の概要については、[通信1 HTTPクライアント説明資料](../document/http.md)を参照せよ。
