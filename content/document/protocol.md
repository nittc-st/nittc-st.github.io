# 通信1

この資料では、通信とはそもそも何か？ということや、
HTTP通信の概要について説明します。

## 通信とは？

そもそも通信(communication) とは、直接やりとりのできない人々や機器同士が、
何らかの道具を使って意思や情報を交換することをいいます。

その中でも、電気信号を用いて、文字や数値、音声などのデータをやりとりする通信を、
電気通信((electric) telecommunication) といいます。

### インターネットと通信

皆さんが当たり前に使っているDiscordやTeams、Googleなどの検索エンジンなど、
インターネットは、この電気通信を用いて情報のやりとりを行います。

また、テレビの放送や信号機の制御なども、もちろん通信が使われています。

ですが、通信が用いられるのは、インターネットや放送のような広い世界だけではありません。

### コンピュータ内部の通信

実は、コンピュータ内部でも、たくさんの通信が行われています。
例えば、PowerPointのスライドを読み込むときを考えると、
そのスライドのデータをストレージ(容量)から処理装置(CPU)に持っていき、
処理が完了したら、また処理装置(CPU)からストレージ(容量)に返します。

また、PCで同時にたくさんのアプリケーションを起動したときに、
その間ではデータのやりとりが行われています。

さらに小さい世界を考えてみましょう。
実は、処理装置(CPU)も、たくさんの部品から出来ています。
これらは相互にデータのやりとりが必要なので、通信が行われています。

このように、通信は広い世界だけでなく、非常に小さな世界でも行われているのです。

## プロトコル

さて、ここまでの説明で、様々なところで通信が行われているということは理解したかと思います。

ここで、通信は様々な人種や言語、様々な種類の電気信号で行われる可能性があります。
もし、機器Aではモールス信号を送信し、機器Bでは地デジ信号を受信しようとすると、どうなるでしょうか？

また、日本語でメールを送りたいが、メールのシステムが英語にしか対応していない場合、
どう通信したら良いでしょうか？

これらを取り決めるのが、プロトコルです。

### 主要なプロトコルとその役割

プロトコルは、通信を行う上で、手順や決まり事、ルールを定めたものを指します。

例えば、高専の出願(略) だと、

- 学生は、個人調査票(中学校の校長が作成した、成績を証明するもの)を中学校に提出する
- 学校は、上を封筒に入れ、教務係に簡易書留で郵送する。
- 志願者が複数名いる場合は、個人毎の出願書類をクリップでまとめる

これが、高専出願の「プロトコル」です。

これと同様に、インターネットにもたくさんのプロトコルが存在します。
その中でも、特によく用いるものを下に示します。

| プロトコル | 役割 |
| ---------- | ---- |
| HTTP/HTTPS | WEBページや文字データを送受信する |
| SSH        | PCに遠隔でログインする            |
| FTP        | ファイルの送受信を行う            |
| SMTP       | メールを送信する                  |
| POP3/IMAP  | メールを受信する                  |
| DHCP       | 通信に必要な情報を自動で設定する  |

普段使っているアプリケーションも、
通信したいデータに応じ、これらのプロトコルを適切に選択することで、
インターネットが利用出来ています。

## クライアントサーバシステム

インターネットの通信において、多くの通信はクライアントサーバ型により提供されます。

クライアントサーバシステムは、私たちが使っているPCやスマートフォンなどの端末であるクライアント、
(HTTPであれば)WEBサイトやログイン情報などを送受信・管理するサーバにより構成されます。

このシステムにおいては、まずクライアントがリクエスト(要求)送信し、
それに応じたメソッド(処理, 機能)をサーバーが実行、返信します。

このように、クライアントサーバシステムは、必ずクライアント側から通信を開始するため、
サーバーから一方的にデータが送られてくることはありません。

## HTTP通信

インターネットのプロトコルの中でも、特に多く用いるのが、HTTPです。
HTTPは、テキストを送受信するためのプロトコルですが、
様々なデータをテキスト形式に変換することで、
多くの通信に応用できる汎用的なプロトコルです。

### HTTP通信の形式

HTTP通信は、すべてテキスト形式で行われます。
これを、HTTPリクエストといいます。

以下に、そのサンプルを示します。

**送信**

```http
GET / HTTP/1.1
Host: example.com
User-Agent: curl/8.18.0
Accept: */*
```

**受信**

```http
HTTP/1.1 200 OK
Date: Fri, 27 Feb 2026 15:43:13 GMT
Content-Type: text/html
Transfer-Encoding: chunked
Connection: keep-alive
CF-RAY: 9d48cbec5e257b69-NRT
Last-Modified: Wed, 25 Feb 2026 07:22:28 GMT
Allow: GET, HEAD
Accept-Ranges: bytes
Age: 12952
cf-cache-status: HIT
Server: cloudflare

<!doctype html><html lang="en"><head><title>Example Domain</title>
(省略)
```

これらが何を表すのかについて、説明します。

### HTTPリクエストの構成

HTTPリクエストは、以下の構成を持ちます。

**送信**

```
<メソッド> <場所(Path)> <バージョン>
<キー>: <値>

<リクエストボディ(ペイロード)>
```

**受信**

```
<バージョン> <ステータスコード> <メッセージ>
<キー>: <値>

<レスポンスボディ(ペイロード)>
```

#### ヘッダ

送信、受信のどちらにおいても、ペイロードを含めない、それより上にある情報をヘッダといいます。
ヘッダは、どんなクライアント、サーバーがどんな通信を行おうとしているのか、という情報を示します。

また、ヘッダのキー、値については情報の種類とその内容を示します。
例えば、キーが`Date`, 値が`Fri, 27 Feb 2026 15:43:13 GMT`だとすると、
通信が行われた日付が`2026年2月27日(金) 世界時15:43:13`であることを示します。

ペイロードは、実際に送信・受信する本体のことを示します。

通常、WEBサイトにアクセスすると、
リクエストボディはなし、レスポンスボディはWEBページになります。

#### ステータスコード

返却された値について、正常であるか、異常であるか、
またその中でもどんな状態かを示す、3桁の値をステータスコードといいます。

ステータスコードは、3桁目で大まかな状態、残り2桁でその分類を表します。
以下に、それぞれの値に対する、その状態(意味)を示します。

| ステータスコード | 状態 |
| ---------------- | ---- |
| 200 | 正常                      |
| 300 | リダイレクト (たらい回し) |
| 400 | ユーザーのリクエスト不正  |
| 500 | サーバーエラー            |

### HTTPリクエストのメソッド

続いて、メソッドについて説明します。

HTTPリクエストにおいては、主に以下のメソッドが存在します。

- HEAD
- GET
- POST

それぞれのメソッドについて、役割と形式を説明します。

#### HEADメソッド

HEADメソッドでは、サーバーにヘッダのみを要求します。
このメソッドは、ある場所(Path)にアクセスしたときに、どのようなデータが得られるのかを確認するために使います。
このリクエストでは、リクエストボディを付加しません。
アクセス先によっては、リクエストボディを付加するとエラーが帰ってくることもあります。

**例**

```http
HEAD / HTTP/1.1
Host: example.com
```

例えば、AというPathがあるとき、HEADメソッドを実行すると、ヘッダに

- `Allow: GET, HEAD`

という記述があったとしましょう。
この場合は、AにGETメソッドを送信することができるということを表します。
このように、パスに応じたデータの内容が不明確である場合に用います。

#### GETメソッド

GETメソッドでは、サーバーにヘッダ及びレスポンスボディ(ペイロード)を要求します。
普通、サーバーにWEBサイトを要求するときは、このメソッドを用います。
このリクエストでは、リクエストボディを付加しません。
アクセス先によっては、リクエストボディを付加するとエラーが帰ってくることもあります。

**例**

```http
GET / HTTP/1.1
Host: example.com
```

上で示したサンプルより、要求したパスのhtmlファイルが返却されていることが分かるかと思います。
なお、画像や実行ファイルを要求した場合は、**一度文字に変換された**ものが返却されます。
（これを、エンコードといいます。）

GETメソッドではサーバーが持っている情報の書き換えを、一切行いません。

#### POSTメソッド

POSTメソッドは、サーバーに対してリクエストボディを送るときに用います。
例えば、検索を行うときや、サーバーに何らかのデータを登録するときは、
GETではなくPOSTを用いる必要があります。

**例**

```http
POST /register HTTP/1.1
Host: example.com

{ "user": "you", "age": 255 }
```

POSTメソッドではサーバーが持っている情報の書き換えを行う場合があります。
つまり、クライアントが送信したデータがサーバーに反映されることがあります。

### URLとパラメータ

GETメソッドにおいては、URLを用いてホストと場所を指示します。
以下に、URLの例を示します。

```
https://www.example.com/example/search?q=aaa&page=2
```

URLは、以下の構造をもつ文字列です。

```
<プロトコル>://<ドメイン>/<場所(Path)>?<キー>=<値>&<キー>=<値>
```

それぞれの要素について説明します。

**プロトコル(スキーム)**

以下のような文字列を用いて、通信の種類を示します。

- http
- https
- ftp
- file
- ssh

**ドメイン(ホスト)**

どのサーバーと通信するかを示す文字列です。
以下にその例を示します。
ドメイン(厳密にはFQDN)は、ドット区切りで要素を表します。

今回においてはその仕組みは重要でないので、省略します。

**場所(Path)**

サーバー内部のファイルの位置を示します。

基本的にはローカルのパスと同様ですが、
ディレクトリを指定すると、自動でファイルが提供される場合があります。
例えば、

```
https://www.google.com
```

にアクセスすると、実際には、

```
https://www.google.com/index.html
```

を取得しています。この設定はサーバーによって異なりますが、
慣習的にindex.htmlが適用されることが多いです。

**URLパラメータ**

`?`記号以降に記述されるキー、値の組をURLパラメータ(または単にパラメータ) といいます。

これらは、引数のようなものであり、例えば検索文字列や結果の数などを設定します。

### 暗号化通信

インターネットは、様々な脅威が無数に存在しています。
送信したデータは容易に盗聴され、不正に利用されます。

これを防ぐ仕組みとして、暗号化が存在します。
暗号化は、以下のような仕組みを指します。

1. クライアントは鍵を作成し、安全な方法でサーバーに渡す。
2. クライアントは鍵を使ってデータを暗号(一見無意味な文字列)に変換し送信する。
3. サーバーは鍵を使って暗号を解読し、クライアントが求めているデータを用意する。
4. サーバーはそのデータを鍵を使って暗号に変換し送信する。
5. クライアントは鍵を使って暗号を解読し、データを得る。

HTTPSというプロトコルでは、通信に暗号化が行われます。(暗号化通信)

GETリクエスト、POSTリクエストのどちらにおいても、**URLは暗号化が行われません。**
つまり、第三者からこの値が容易に取得できるということです。

そのため、URLパラメータでパスワードや個人情報を渡してはいけません。
(これは、開発者側が注意することです。)
